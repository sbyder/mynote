本分册围绕一个核心问题组织：**模型应该如何同时理解视频中的空间信息、时间变化和跨时间事件关系？** 重点不是背诵网络名称，而是比较各种时空归纳偏置、特征表示与算力取舍。

---

## 1. 视频比图像多了什么

视频可以写作：

$$
X\in\mathbb R^{N\times C\times T\times H\times W}
$$

- $N$：批次大小
- $C$：颜色或特征通道（RGB 通常为 3）
- $T$：帧数 / 时间位置
- $H,W$：空间尺寸

视频不仅包含每帧的物体、纹理、场景，还包含运动方向、速度、事件先后顺序、远距离状态变化等信息。

### 1.1 三种不同的关系

| 关系 | 例子 | 常见建模手段 |
|---|---|---|
| 帧内空间关系 | 边缘、局部形状 | 2D CNN / 空间 Attention |
| 局部时间关系 | 球向右运动、手臂挥动 | 光流 / 3D CNN / 时间卷积 |
| 长距离事件关系 | 先拿钥匙，过一会儿再开门 | 长时序聚合 / Temporal Attention |

时间维度有独立意义，不等于 RGB 通道；但**张量是否保留时间轴**与**模型是否具备时序归纳偏置**也要分开判断。

## 2. 从 Early Fusion 到 Late / Slow Fusion

### 2.1 Early Fusion：把帧堆叠为输入通道

一种经典 Early Fusion 实现是把 $T$ 张 RGB 帧沿通道拼接：

$$
(T,3,H,W)\longrightarrow(3T,H,W)
$$

例如 4 帧 RGB 变成 12 通道的二维 CNN 输入：

~~~text
Frame 1: R1 G1 B1 ─┐
Frame 2: R2 G2 B2 ─┤
Frame 3: R3 G3 B3 ─┼→ Conv2D(in_channels=12)
Frame 4: R4 G4 B4 ─┘
~~~

注意：

1. **不同帧顺序没有在数学上完全丢失**：不同帧占不同通道，卷积可学习跨帧组合。
2. **没有时间平移共享**：空间卷积核在图像平面滑动，但通常不会沿着“帧序号”滑动。
3. **首层输入通道固定**：改变堆叠帧数通常需要改变第一层的参数形状。
4. **Early Fusion 是融合时间早晚的概念**，不严格等于唯一的通道堆叠实现。

### 2.2 Late Fusion 与 Slow Fusion

- **Late Fusion**：先对每帧或片段分别提取表示，在较深层或预测阶段组合。
- **Slow Fusion**：分多层逐步交换相邻时间信息，而非第一层就完成全部混合。

两者的区别主要是**时间信息在哪个阶段开始交互**。

## 3. 光流与经典 Two-Stream 网络

### 3.1 光流（Optical Flow）

光流估计相邻帧之间图像内容的表观运动：

$$
F(x,y)=(u(x,y),v(x,y))
$$

- $u$：水平表观位移
- $v$：垂直表观位移

每对相邻帧通常产生 $2\times H\times W$ 的流场。堆叠 10 组光流，可以形成 $20\times H\times W$ 的二维 CNN 输入。

光流并不直接等于真实三维速度：摄像机运动、遮挡、亮度变化等都影响估计。

### 3.2 Two-Stream（双流）网络

代表论文：*Two-Stream Convolutional Networks for Action Recognition in Videos*（Simonyan 与 Zisserman，2014）。

~~~text
                     原始视频
                    /        \
            选取 RGB 帧     计算连续光流
                |               |
           Spatial CNN      Temporal CNN
          外观、物体、场景   运动模式
                \               /
                 预测分数融合
                       |
                    动作类别
~~~

双流的划分依据是**输入信息类型**：RGB 外观与光流运动。经典版本常在预测层融合，也有后来改进采用中间特征融合。

这与 SlowFast（用不同时间采样率划分路径）不是同一套分工。

### 3.3 光流与 Embedding 的联系

两者都属于把原始数据变成后续网络更易使用的表示：

$$
x\xrightarrow{\phi}z\xrightarrow{f_\theta}\hat y
$$

但传统光流有明确的人为目标——估计表观运动；Embedding 往往由训练目标驱动学习，可表示更广泛的语义特征。

**特征提取准确不等于下游任务表现必然最好。** 精准运动场未必足以区分“挥手”和“擦窗”；语义相近的嵌入也不一定最适合所有分类任务。

对于固定的光流预处理，动作分类 Loss 通常不能更新光流算法；若使用可微的运动编码器并联合训练，才有机会进行端到端优化。

## 4. 3D CNN：沿时间与空间滑动

2D 卷积的 Filter 形状：

$$
W_{\mathrm{2D}}\in
\mathbb R^{C_{out}\times C_{in}\times K_h\times K_w}
$$

3D 卷积的 Filter 形状：

$$
W_{\mathrm{3D}}\in
\mathbb R^{C_{out}\times C_{in}\times K_t\times K_h\times K_w}
$$

这里“3D”是指**时间、高度、宽度三个卷积方向**，并不要求显式重建场景的三维几何。

### 4.1 局部时空计算

$$
Y_{o,t,h,w}
=
b_o+\sum_{c,\tau,i,j}
W_{o,c,\tau,i,j}
X_{c,t+\tau,h+i,w+j}
$$

式中省略 Stride / Padding / Dilation 的索引细节。

例如 $3\times3\times3$ 卷积，每次观察连续三帧的局部 3×3 区域，并在后续时间、空间位置重复使用同一组权重。

~~~text
时间 →  t0      t1      t2      t3      t4
         |       |       |       |       |
         └───────┴───────┘
            3 帧窗口   ─────────→ 下一时刻的 3 帧窗口
        每帧都取局部 3×3 空间区域
~~~

**核心归纳偏置：相同局部运动模式可以出现在不同时间位置。** Early Fusion 通道堆叠没有直接内建这种时间平移共享。

### 4.2 张量 Shape 与 PyTorch

~~~python
import torch
from torch import nn

# [batch, channels, time, height, width]
x = torch.randn(2, 3, 16, 112, 112)
conv = nn.Conv3d(
    in_channels=3,
    out_channels=64,
    kernel_size=(3, 3, 3),
    padding=(1, 1, 1),
    stride=(1, 1, 1),
)
y = conv(x)
print(y.shape)  # [2, 64, 16, 112, 112]
~~~

这里保持了时间长度。若分类整个片段，可在末端同时对 $T,H,W$ 做 Global Average Pooling；若需要事件时间定位，则应保留足够的时间分辨率。

### 4.3 成本与局限

不计 Bias，标准 3D 卷积参数量：

$$
P=K_tK_hK_wC_{in}C_{out}
$$

在其他设置相同的条件下，$K_t=3$ 时比对应 2D 卷积多 3 倍卷积核参数；实际计算与显存还取决于输出时间长度。

局部时间核擅长短期运动，但对跨度很长的事件关系，需要堆叠多层、扩大感受野、时间下采样或引入全局交互机制。

### 4.4 代表：C3D 与 I3D

- **C3D**：*Learning Spatiotemporal Features with 3D Convolutional Networks*（2015），系统使用小型 3D 卷积核学习时空特征。
- **I3D**：*Quo Vadis, Action Recognition? A New Model and the Kinetics Dataset*（2017），将二维卷积核扩展（Inflate）为三维卷积核，便于利用图像预训练权重；原研究也讨论了 RGB 与光流双流组合。

## 5. R(2+1)D：分离空间与时间卷积

代表论文：*A Closer Look at Spatiotemporal Convolutions for Action Recognition*（2018）。

完整卷积：

$$
K_t\times K_h\times K_w
$$

可分解为：

$$
(1\times K_h\times K_w)
\quad\rightarrow\quad
(K_t\times1\times1)
$$

~~~text
视频特征
   ↓
1×3×3 空间卷积
   ↓
ReLU 等非线性
   ↓
3×1×1 时间卷积
   ↓
时空表示
~~~

### 5.1 不只是为了省算力

这种分解有三重可能价值：

1. **显式结构归纳偏置**：先提取空间特征，再聚合时间变化。
2. **更多非线性**：空间与时间操作之间可以插入额外激活函数，提升表示灵活性。
3. **优化更容易**：论文报告在所研究设置下，比直接使用完整 3D 卷积更容易优化。

两种方法未必谁的参数更少。通过选择中间通道数 $M$，可使分解卷积与完整 3D 卷积具有近似相同的参数量（忽略 Bias）：

$$
K_tK_hK_wC_{in}C_{out}
\approx
K_hK_wC_{in}M+K_tMC_{out}
$$

因此性能提升不能简单归因于“省参数”。

## 6. SlowFast：两种时间采样速率

代表论文：*SlowFast Networks for Video Recognition*（2019）。

SlowFast 使用同一段 RGB 视频构建两条不同路径：

| | Slow Pathway | Fast Pathway |
|---|---|---|
| 采样频率 | 低，时间稀疏 | 高，时间密集 |
| 通道容量 | 较大 | 较小 |
| 倾向提取 | 外观、场景与语义 | 运动与快速变化 |
| 输入 | RGB 帧 | RGB 帧，通常不要求外部光流 |

**“Slow/Fast”指时间采样频率，不是分支运行速度。**

### 6.1 两个重要超参数

$$
\alpha=\frac{T_{fast}}{T_{slow}},
\qquad
\beta=\frac{C_{fast}}{C_{slow}}
$$

经典配置中常见 $\alpha=8,\ \beta=1/8$。

例如同一段 64 帧片段：

~~~text
Slow：每 16 帧采样 1 帧 → 4 帧，通道较多
Fast：每  2 帧采样 1 帧 → 32 帧，通道较少
~~~

Fast 看更多时间点，却不必为每个时间点维持很大的外观特征容量。这是按信息变化速度分配计算预算的设计。

### 6.2 Lateral Connection（横向连接）

两条路径不是完全独立地训练、最后才合并；网络中间通过 Lateral Connection 交换特征：

~~~text
原始视频
   ├── 稀疏采样 → Slow ────── Slow ────── Slow ──┐
   │                    ↑           ↑             │
   │                 Lateral     Lateral          │
   │                    │           │             │
   └── 密集采样 → Fast ────── Fast ────── Fast ──┤
                                                   ↓
                                            融合与动作分类
~~~

Fast 和 Slow 的时间长度不同，因此融合前需要在时间维度对齐，例如使用带时间步长的卷积。

### 6.3 与经典 Two-Stream 的不同

- Two-Stream：**按模态 / 特征类型分流**（RGB 与光流）。
- SlowFast：**按时间分辨率与通道容量分流**（通常两条都是 RGB）。

Slow 路径不等于完全不学运动，Fast 路径也不等于完全不学语义；这是结构倾向，而非硬性分工。

### 6.4 局限与启发

两条路径的采样频率通常是固定配置，对不同视频、不同事件的实际信息密度未必最优。

由此引出自适应帧采样、动态 Token 选择、任务条件化计算分配等研究方向。见：[研究构想与开放问题.md](./研究构想与开放问题.md)。

## 7. Video Transformer：完整与分离式时空 Attention

把每帧切成 $P$ 个 Patch，共 $T$ 帧，可以得到：

$$
N=TP
$$

若所有时空 Token 都能直接相互关注，单个注意力头的分数矩阵有：

$$
N^2=T^2P^2
$$

个元素。这里忽略 CLS Token、特殊 Token、Tubelet 压缩等因素。

### 7.1 Full Space-Time Attention

全部时空 Token 参与同一套注意力运算。

- 优势：可以直接建立跨空间、跨时间的长距离关系。
- 代价：密集 Attention 的计算通常与 $N^2$ 成正比，长视频成本快速增长。

### 7.2 Divided Space-Time Attention

例如 TimeSformer（2021）的分离式时空注意力：先沿时间维交互，再沿空间维交互。

简化匹配规模：

$$
O(PT^2+TP^2)
$$

相对于完整时空交互：

$$
O(T^2P^2)
$$

这样做不仅可以减少计算，也可能通过结构归纳偏置改善训练；但单层不再执行所有时空位置之间的直接两两匹配。

### 7.3 FlashAttention 改变什么

FlashAttention 是**完整密集注意力的执行算法优化**，通过分块计算与更合理的显存读写策略，避免显式保存整个 $N\times N$ 注意力矩阵。

它不等于稀疏注意力，也不会在一般情况下把精确密集注意力的计算量从平方级变成线性级。

因此即使 GPU 显存与算力持续提升，分解 Attention、局部窗口、稀疏计算与 Token 选择仍然有研究价值。

### 7.4 交互：帧数与 Attention 规模

假设每帧为 $224\times224$，按 $16\times16$ Patch 切分，每帧 $P=196$ 个 Token，不使用时间 Tubelet 压缩。

## 8. 时间编码：RoPE 与视频

视频 Transformer 可给每个 Token 指定时间与空间坐标 $(t,h,w)$，并通过位置编码让模型区分顺序和位置。

RoPE（旋转位置编码）可以将位置相关的旋转作用于 Q、K，使其点积包含相对位置关系。视频模型还可以在时间、高度、宽度等轴上使用相应扩展。

但在普通 Early Fusion 的 Conv2D 输入通道中对各帧做 RoPE 式旋转，**不会自动获得 Attention 的相对位置点积性质**；因为 Conv2D 的通道加权运算不是 $QK^\top$。

可行的做法包括：

- 给帧特征添加时间位置编码，再用二维网络融合。
- 使用时间卷积或 3D CNN，直接引入时间局部性与权重共享。
- 将帧 / Patch 变为 Token，使用时间 Attention 与 RoPE。

“时间信息被编码进去”和“网络能高效利用时间关系”是两个不同层次的问题。

## 9. 选择架构时要问什么

| 架构 | 时序信息从哪里来 | 核心归纳偏置 / 取舍 |
|---|---|---|
| Early Fusion | RGB 多帧堆叠 | 早期混合，时间平移共享弱 |
| Two-Stream | RGB + 光流 | 人为分离外观与运动 |
| 3D CNN / C3D | RGB 时空体 | 局部时空共享权重 |
| I3D | 二维网络扩展为三维 | 借助图像预训练与时空卷积 |
| R(2+1)D | 分解空间与时间卷积 | 额外非线性、优化便利 |
| SlowFast | 不同帧率的 RGB 路径 | 按时间频率分配表示容量 |
| Video Transformer | 时空 Token | 动态跨位置交互 |
| Divided Attention | 时间与空间分阶段 Attention | 减少匹配规模，加入轴向偏置 |

注意区分三个问题：

1. **表达能力**：模型理论上能表示哪些关系？
2. **学习难度**：给定数据和优化过程，哪些关系更容易被学到？
3. **计算效率**：这些关系的参数量、FLOPs、显存访问、推理延迟分别是多少？

完整交互不一定在有限数据和预算下效果最好；分解也不必然损失实用表现。
